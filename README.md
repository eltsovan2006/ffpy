# ffpy

Программа (консольная `ffpy.exe` и графическая `ffpy-gui.exe`), которая читает
входные файлы в формате Firefly/GAMESS,
считает их через [PySCF](https://pyscf.org) и пишет вывод для Chemcraft,
Avogadro, Jmol и Molden. Собственная реализация по открытой документации и
формату файлов, не копия Firefly.

```
ffpy water.inp
```

На выходе:

| Файл | Что внутри | Кто читает |
|---|---|---|
| `water.out` | лог: вход с применёнными умолчаниями, ход SCF, энергии, орбитали, заряды Малликена и Лёвдина, диполь, шаги оптимизации, частоты, термохимия, время | человек |
| `water.molden` | геометрия, базис, орбитали; частоты и нормальные моды; путь оптимизации | Chemcraft, Avogadro, Jmol, Molden |
| `water.dat` | итоговая геометрия `$DATA` и орбитали `$VEC` для `GUESS=MOREAD` | ffpy |
| `water.xyz` | траектория оптимизации | любой просмотрщик |

Последняя строка `.out` — `ffpy TERMINATED NORMALLY` или
`ffpy TERMINATED ABNORMALLY: ERROR CODE n (...)`; тот же код возвращает
процесс, так что скрипты могут проверять результат.

## Установка на Windows

### Вариант 1. Автоустановщик (рекомендуется)

Скачайте `ffpy-0.3.2-setup.exe` со страницы [релиза](https://github.com/eltsovan2006/ffpy/releases) и следуйте мастеру установки:
* Устанавливает программу в выбранную папку (по умолчанию `C:\ffpy`).
* Автоматически добавляет путь в переменную `PATH`.
* Создаёт ярлык `ffpy-gui` на Рабочем столе и в меню «Пуск».
* Ассоциирует входные файлы `.inp` с `ffpy-gui.exe`.

### Вариант 2. Портативная сборка (ZIP-архив)

1. Распакуйте `ffpy-0.3.2-win64.zip` в любую папку, например `C:\ffpy`.
2. При необходимости добавьте команду `ffpy` в переменную `PATH`, запустив `add_to_path.ps1`:
   ```
   powershell -ExecutionPolicy Bypass -File C:\ffpy\add_to_path.ps1
   ```
3. В новом терминале: `ffpy C:\ffpy\examples\water_opt.inp`.

Без терминала удобнее всего работать в `ffpy-gui.exe` (см. ниже). Можно
также перетащить `.inp` на `ffpy.exe` — окно останется
открытым до нажатия Enter, а результаты появятся рядом с входным файлом.

Python и conda для готовой сборки не нужны: PySCF, geomeTRIC, NumPy и все
DLL лежат в папке `_internal`. PySCF официально не поддерживает Windows, но
conda-forge собирает PySCF 2.14 под win-64; эта сборка и упакована в exe.

## Установка на macOS (Apple Silicon)

### Установка из DMG-образа (рекомендуется)

1. Скачайте `ffpy-0.3.2-macos-arm64.dmg` со страницы [релиза](https://github.com/eltsovan2006/ffpy/releases).
2. Откройте скачанный `.dmg` файл и перетащите `ffpy.app` в папку `Программы` (`Applications`).
3. Для работы в терминале консольный бинарник находится внутри бандла: `/Applications/ffpy.app/Contents/MacOS/ffpy`.

Также доступна портативная сборка в виде ZIP-архива `ffpy-0.3.2-macos-arm64.zip` (распакуйте в удобную папку и запускайте `ffpy` или `ffpy-gui`).

### Первый запуск и обход предупреждения Gatekeeper

Приложение не подписано платным сертификатом Apple Developer ID, поэтому при первом запуске macOS Gatekeeper заблокирует его («приложение повреждено» или «не удалось проверить разработчика»). Разрешить запуск можно любым из трёх способов:

1. **Правый клик (быстрый способ):** в Finder откройте папку «Программы», зажмите клавишу `Control` (или нажмите правой кнопкой мыши) на `ffpy.app`, выберите пункт **Открыть** в меню, а затем нажмите кнопку **Открыть** в диалоговом окне подтверждения.
2. **Системные настройки:** после попытки запуска откройте **Системные настройки → Конфиденциальность и безопасность**, прокрутите страницу вниз до блока «Безопасность» и нажмите кнопку **Всё равно открыть** рядом с предупреждением о блокировке `ffpy.app`.
3. **Команда в Терминале:** откройте Терминал и снимите флаг карантина macOS:
   ```bash
   xattr -dr com.apple.quarantine /Applications/ffpy.app
   ```
   (для портативной сборки из ZIP укажите путь к распакованной папке: `xattr -dr com.apple.quarantine /путь/к/ffpy`).

## Графический интерфейс (ffpy-gui.exe)

`ffpy-gui.exe` лежит рядом с `ffpy.exe`. Он открывает и редактирует `.inp`,
показывает логи `.out` и запускает расчёты; сами расчёты выполняет тот же
`ffpy.exe`.

* **Редактор `.inp`** — подсветка групп, ключей, чисел и комментариев, номера
  строк, поиск и замена (Ctrl+F / Ctrl+H), переход к строке (Ctrl+G),
  закомментировать строки (Ctrl+/). Вход проверяется прямо во время набора
  теми же правилами, что и в `ffpy`: ошибка видна в строке состояния и
  в панели «Проверка входа», строка с ошибкой подсвечивается.
* **Просмотр `.out`** — только чтение, подсветка WARNING/ERROR и разделов,
  список «Раздел» для перехода, поиск, «Копировать всё» (Ctrl+Shift+C),
  «Сохранить копию…». Открытый лог обновляется сам, когда файл меняется.
* **Запуск** — F5 сохраняет и запускает текущий `.inp`; лог идёт в панель
  «Журнал запуска» в реальном времени. Несколько файлов (или «Запустить все
  .inp в папке») встают в очередь. Shift+F5 останавливает расчёт.
* **Результаты** — сводка по `.out`: статус, итоговая энергия (с кнопкой
  копирования), геометрия, частоты с ИК, возбуждённые состояния,
  предупреждения; ссылки на `.out/.dat/.xyz`, `.molden` открывается в
  программе, связанной с этим типом файлов (Chemcraft, Avogadro).
* **Файлы** — дерево рабочей папки (показывает только файлы ffpy): открыть,
  запустить, переименовать, дублировать, копировать в другую папку,
  скопировать путь, удалить в корзину, показать в проводнике; файлы можно
  перетаскивать в Проводник и из Проводника в окно.
* **Новый расчёт…** (Ctrl+Shift+N) — конструктор: метод, функционал, базис,
  тип задачи, заряд и мультиплетность, возбуждённые состояния, растворитель,
  CASSCF, геометрия из текста или `.xyz`; готовый вход виден и проверяется
  до создания.

Из исходников GUI запускается так: `python -m ffpy.gui [файлы]`.

## Параметры командной строки

```
ffpy input.inp [-o OUTDIR] [-n NPROC] [--gamess] [--check] [--debug] [-q]
ffpy --keywords      список групп и ключей
ffpy --version
```

* `-n` — число потоков (по умолчанию min(8, ядра): для молекул учебного
  размера больше 8 потоков не ускоряет расчёт).
* `--gamess` — добавить в `.out` GAMESS-подобные блоки (координаты,
  `FINAL ... ENERGY IS`, `EIGENVECTORS`, `NSERCH`, `FREQUENCY:`). Формат
  написан по общему знанию вывода GAMESS и не сверен с примерами из
  дистрибутива Firefly.
* `--check` — только прочитать и проверить вход (то же, что `EXETYP=CHECK`).
* `--debug` — дополнительно записать подробный лог PySCF (`имя.pyscf.log`).
* `--json` — машиночитаемый вывод для скриптов и ИИ-инструментов:
  `ffpy --keywords --json` (таблица ключей), `ffpy --check --json x.inp`
  (результат проверки), `ffpy x.out --json` (числа из готового `.out`),
  `ffpy x.inp --json` (посчитать и напечатать JSON-сводку).

## Подключение к ИИ (MCP-сервер)

`ffpy-mcp` — сервер по протоколу [MCP](https://modelcontextprotocol.io):
он позволяет ИИ-помощнику (Claude, ChatGPT, Gemini CLI, Cursor, VS Code и
любой другой клиент с поддержкой MCP) проверять входные файлы, запускать
расчёты и читать результаты. Сервер не привязан к конкретному ИИ.

**Установка** (нужен Python 3.11+ и ffpy из исходников):

```
pip install -e ".[mcp]"
```

Появится команда `ffpy-mcp`. Если её нет в PATH, используйте
`python -m ffpy.mcp_server`.

**Инструменты:**

| Инструмент | Что делает |
|---|---|
| `list_keywords` | поддерживаемые группы и ключи (тип, значение по умолчанию, допустимые значения) |
| `validate_input` | проверить текст входа без запуска (ошибка со строкой, предупреждения) |
| `write_input` | сохранить `.inp` в рабочую папку |
| `list_files`, `read_file` | посмотреть файлы рабочей папки и прочитать текстовый файл (можно только хвост) |
| `parse_output` | числа из `.out`: статус, энергии, длины связей, углы, заряды, частоты, возбуждённые состояния |
| `run_calculation`, `job_status`, `cancel_job` | запустить расчёт в фоне, узнать состояние, остановить. **По умолчанию выключены**, включаются флагом `--allow-run` |

**Безопасность.** Сервер работает только внутри одной рабочей папки
(`--workdir`, по умолчанию `~/ffpy-work`): пути с `..` и абсолютные пути
отклоняются. Запуск расчётов включается явно, по умолчанию идёт один
расчёт одновременно (`--max-jobs`) с лимитом времени (`--timeout`, секунды,
по умолчанию 3600).

**Настройка клиента.** Во всех клиентах нужно указать команду запуска
сервера; ниже готовые фрагменты. Замените `/путь/к/python` на Python, где
стоит ffpy (в conda: `conda run -n ffpy which python`), а `/путь/к/рабочей/папке` —
на свою папку.

*Claude Desktop* (`claude_desktop_config.json`), *Cursor* (`.cursor/mcp.json`)
и *Claude Code* (`.mcp.json`) принимают одинаковый блок:

```json
{
  "mcpServers": {
    "ffpy": {
      "command": "/путь/к/python",
      "args": ["-m", "ffpy.mcp_server", "--workdir", "/путь/к/рабочей/папке", "--allow-run"]
    }
  }
}
```

*VS Code* (`.vscode/mcp.json`):

```json
{
  "servers": {
    "ffpy": {
      "type": "stdio",
      "command": "/путь/к/python",
      "args": ["-m", "ffpy.mcp_server", "--workdir", "/путь/к/рабочей/папке", "--allow-run"]
    }
  }
}
```

*Gemini CLI* (`~/.gemini/settings.json`) — тот же блок `mcpServers`, что и
выше. *Другие клиенты* (в том числе ChatGPT с поддержкой локальных
MCP-серверов): в настройках добавьте stdio-сервер с той же командой и
аргументами. Чтобы только проверять входы и читать результаты, уберите
`--allow-run`.

**Проверка.** Запустите клиента и попросите, например: «проверь вход
для воды MP2/6-31G*, запусти и скажи энергию». Сервер можно проверить и без
ИИ через [MCP Inspector](https://github.com/modelcontextprotocol/inspector):
`npx @modelcontextprotocol/inspector python -m ffpy.mcp_server`.

Если MCP недоступен, те же возможности есть у `ffpy --json` (см. выше):
его выводом можно пользоваться из любого скрипта.

> В Windows-сборке (`ffpy-<версия>-win64.zip`) `ffpy-mcp` пока не входит;
> используйте установку из исходников.

## Что умеет 0.3.2

* HF: RHF, UHF, ROHF; DFT (`DFTTYP=B3LYP, PBE0, PBE, BLYP, M06-2X, ...`);
  MP2 (`MPLEVL=2`, по умолчанию с замороженным остовом); TDHF/CIS/TDDFT/TDA
  (`$TDDFT NSTATE=`, `CITYP=CIS`); CASSCF (`SCFTYP=MCSCF` + `$DET`);
  растворитель IEF-PCM (`$PCM SOLVNT=WATER`).
* `RUNTYP=ENERGY, GRADIENT, OPTIMIZE, HESSIAN`; частоты, ИК-интенсивности,
  термохимия при нескольких температурах (`$FORCE TEMP(1)=...`),
  `$STATPT HSSEND=.TRUE.`.
* Базисы `GBASIS=STO, N21, N31, N311` с `NGAUSS/NDFUNC/NPFUNC/NFFUNC/DIFFSP/DIFFS`,
  а также `CCD, CCT, CCQ, ACCD, ACCT, ...`.
* Точечные группы в `$DATA` (Cs, Ci, Cn, Cnv, Cnh, Dn, Dnh, Dnd, S2n, T, Td,
  Th, O, Oh): атомы размножаются по симметрии, расчёт идёт в C1.

Полный список ключей, значения по умолчанию и таблица «метод × RUNTYP» —
в [docs/KEYWORDS.md](docs/KEYWORDS.md). Чего нет: XMCQDPT2, FMO,
P2P-параллелизм, ECP, z-матрица, побитовое совпадение с Firefly.

## Точность относительно Firefly

Ожидаемые расхождения: HF/MP2 — около 1·10⁻⁶ Eh, DFT — до 1·10⁻⁴ Eh из-за
других сеток и формы VWN в B3LYP. Для проверки: оптимизация воды
RHF/6-31G* даёт E = −76.0107465 Eh, r(OH) = 0.9473 Å, ∠HOH = 105.50°,
частоты 1826.6 / 4070.5 / 4188.7 см⁻¹ — в пределах допусков от известных
значений GAMESS для этой задачи.

Эталонные числа в `tests/reference.json` пока сгенерированы самим ffpy
(`"source": "ffpy-regression"`). Их нужно заменить числами настоящего
Firefly, запущенного как чёрный ящик на тех же входах из `tests/inputs`.

## Разработка

```
conda env create -f environment.yml
conda activate ffpy
python -m ffpy examples\water_opt.inp
python -m pytest
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

`build.ps1` собирает `dist\ffpy\ffpy.exe` (PyInstaller, one-folder),
прогоняет на нём пример с водой и упаковывает `dist\ffpy-<версия>-win64.zip`.

Устройство:

```
ffpy/
  cli.py          запуск, коды выхода, .out
  parser.py       группы $...$END -> словари, проверка ключей
  schema.py       поддерживаемые группы, ключи, умолчания
  job.py          Job: молекула, базис, метод, RUNTYP; разбор $DATA/$VEC
  symmetry.py     размножение атомов по точечной группе
  basis_map.py    GBASIS/NGAUSS/NDFUNC -> имя базиса PySCF
  xc_map.py       DFTTYP -> строка xc PySCF
  dispatcher.py   обработчик на каждую пару метод x RUNTYP
  methods.py      сборка объектов PySCF
  runners/        energy, gradient, optimize, hessian, report
  writers/        out, molden, dat, xyz, gamess
tests/
  inputs/         входы тестового набора
  reference.json  эталонные числа и допуски
```

Правовая рамка: источники — документация, примеры input/output и запуск
Firefly как чёрного ящика. Бинарники Firefly не дизассемблируются, файлы
дистрибутива в репозиторий не кладутся. Сторонние библиотеки в сборке —
см. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
