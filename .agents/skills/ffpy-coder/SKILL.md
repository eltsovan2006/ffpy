# ffpy-coder (Antigravity)

Ты основной исполнитель. Работай до конца, не останавливайся на полпути: сам запускай тесты, сам исправляй ошибки, сам проверяй свой diff. Claude получает только твой итог, его лимит дорогой.
Режим выбирай по запросу пользователя.

---
## Режим SETUP (первый запуск)
1. Проверь в терминале: `git --version`, `python --version`. Если чего-то нет, скажи пользователю, что поставить (`winget install Git.Git`, `winget install Python.Python.3.12`), и остановись.
2. Нет git-репозитория → `git init` и первый коммит. Допиши в `.gitignore` строки из `gitignore-additions.txt` (если файл есть), потом удали этот файл.
3. Окружение описано в разделе Environment файла `AGENTS.md` (conda-окружение из `environment.yml`, Python 3.11). Не создавай `.venv`, если можешь собрать conda-окружение.
   На macOS: нет conda/mamba → скажи пользователю выполнить `brew install --cask miniforge` и остановись. Есть → `conda env create -f environment.yml`; если win-64-пакеты не ставятся, собери окружение `ffpy` через pip (pyscf, geometric, pyside6, pytest) и напиши об этом в ENV.md.
   Путь к python окружения запиши в ENV.md строкой `FFPY_PYTHON=<путь>` (его используют `tools/accept.py` и `tools/auto.py`).
4. `AGENTS.md` уже описывает проект: ничего не переписывай и не придумывай TODO. Только проверь, что строка «Тесты:» в разделе «ИИ-workflow» рабочая.
5. Создай `.ai/TASKS.md` из `.ai/TASKS.template.md`, если его нет.
6. Запусти тесты. Тестов нет → напиши спецификацию `.ai/tasks/000.md` «Эталонные тесты H2, H2O, CH4 (RHF/STO-3G)» по режиму ЧЕРНОВИК.
7. Запиши `.ai/ENV.md`: ОС, версии git и python, venv, результат тестов, открытые проблемы.
8. Закоммить на основной ветке: `git add -A && git commit -m "setup: AI workflow"`.
9. Ответь пользователю 5 строками: что готово и что сделать руками.

## Режим ЧЕРНОВИК (спецификация по запросу пользователя)
1. Номер = максимальный номер в `.ai/TASKS.md` и `.ai/tasks/` плюс 1, три цифры.
2. Изучи код и напиши `.ai/tasks/NNN.md` по `.ai/tasks/_TEMPLATE.md`:
   - одна цель; задачу больше ~150 строк изменений разбей на несколько NNN;
   - Scope — минимальный список реальных путей;
   - критерии приёмки проверяемы тестами; для бага первый критерий — тест, который воспроизводит баг;
   - если не уверен в эталонном числе, пиши `ЭТАЛОН: уточнить`, а не выдумывай.
3. Добавь строку в `.ai/TASKS.md` со статусом `draft`. Если задача рутинная (UI, рефакторинг, без физики), ставь статус `todo`.
4. Закоммить на основной ветке: `git commit -am "spec NNN"` (новые файлы предварительно добавь через `git add`).
5. Ответь одной строкой: номер, статус и нужна ли проверка Claude (да, если затронута физика или архитектура).

## Режим ЗАДАЧА (выполнить `.ai/tasks/NNN.md`)
1. **Ещё на основной ветке** прочитай спецификацию `.ai/tasks/NNN.md`, `.ai/NOTES.md` и, если есть, `.ai/feedback/NNN.md` (замечания имеют приоритет). Свежие версии этих файлов лежат только в основной ветке.
2. Запомни основную ветку. Создай `git checkout -b gemini/NNN` или переключись на неё, если она уже есть.
3. **Сначала тест** под критерии приёмки, потом минимальная реализация.
4. **Цикл до зелёного:** запусти полный набор тестов → исправь → повтори. Не сдавайся после первой неудачи. Чужие красные тесты, которые были красными до тебя, не чини, только перечисли их.
5. **Самопроверка:** посмотри `git diff <основная>...HEAD` и проверь по списку:
   - все критерии выполнены;
   - нет файлов вне Scope (кроме `tests/` и `.ai/reports/`);
   - единицы и допуски соответствуют AGENTS.md;
   - эталоны не подогнаны;
   - нет отладочного мусора.
   Если что-то не так, вернись к шагу 4.
6. Напиши отчёт `.ai/reports/NNN.md` (формат ниже). Закоммить всё в `gemini/NNN`, вернись на основную ветку.
7. Ответь пользователю одной строкой: `NNN готово, передай Claude: «ffpy: прими NNN»`. Если не вышло: `NNN: partial, причина ...`.

### Границы
- Не меняй: `.ai/tasks/`, `.ai/TASKS.md`, `.ai/feedback/`, `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/`, `tools/accept.py`.
- Без слияния в основную ветку, без push.
- Файл вне Scope действительно нужен → не трогай его, напиши об этом в отчёте.

### Формат отчёта (≤ 40 строк)
```
# Отчёт NNN
STATUS: done | partial | failed
## Сделано
- файл — что изменено
## Тесты
- добавлены: ...
- результат: N passed, M failed (какие и почему)
## Самопроверка
- все пункты чек-листа ок / что не ок
## Не сделано / проблемы
-
## Нужно вне scope
-
## Для NOTES
- (0–2 строки)
```
Честный `partial` лучше, чем `done` с неработающим кодом.
